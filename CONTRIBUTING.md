## 📌 Before You Contribute

Please take a moment to review the guidelines below before submitting your contribution.  
Following these rules helps keep the repository **clean, consistent, and easy to explore**.

---

## ✅ Contribution Checklist

Before opening a Pull Request, make sure:

- [ ] 🔍 You have searched the existing list to avoid duplicate APIs.
- [ ] 📦 You are adding one API per Pull Request.
- [ ] ✍️ The API title is clear and properly capitalized.
- [ ] 📝 The description is short, simple, and easy to understand.
- [ ] 🔤 The description ends with a full stop (`.`).
- [ ] ✅ Spelling and grammar have been reviewed.
- [ ] 🧹 Trailing whitespace has been removed.
- [ ] 📖 The Pull Request title and description clearly explain your changes.
- [ ] 🟢 Open-source APIs are marked with the appropriate open-source icon.
- [ ] 💸 Trial/demo-based APIs are marked with the `💸` emoticon.
- [ ] 🔤 APIs are kept in alphabetical order.
- [ ] 📚 The API links directly to its official documentation whenever possible.

## 🔤 Keep the List Organized

Please maintain **alphabetical order** when adding APIs.

This makes it easier for developers to browse and discover APIs quickly.

> 💡 **Tip:** Before submitting your PR, check the entries immediately before and after your addition to ensure the ordering is correct.

---

## 🚀 Pull Request Guidelines

Please keep Pull Requests focused and easy to review.

### Do

- ✅ Submit **one API per Pull Request**.
- ✅ Use a descriptive Pull Request title.
- ✅ Explain what API you are adding.
- ✅ Include the official documentation link.
- ✅ Follow the existing formatting.
- ✅ Check your Markdown before submitting.

### Avoid

- ❌ Duplicate APIs.
- ❌ Multiple unrelated changes in one PR.
- ❌ Long or unnecessary descriptions.
- ❌ Broken or unofficial links.
- ❌ Changes that don't follow the repository's formatting.
